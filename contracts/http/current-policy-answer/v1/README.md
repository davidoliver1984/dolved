# Current-policy answer v1 — Stop 2 backend

ADR-0040. Default-off, server-selected `current-policy-pool-v1`. This is not the legacy generation contract and does not fabricate aspect ownership. `AnswerCurrentPolicyMessage` is the backend entry point; existing conversation delivery still refuses this profile until Stop 3. No user-facing API resource, SSE or web integration is included here.

## Retrieval and context

The existing signed needs planner, catalogue validation, membership scope, eligibility, hydration/integrity, reranker and threshold policy are reused. Current-policy execution directly enters those current-only lanes, never `handleNeeds`' historical discovery/alternatives or coverage selector. A compatible active threshold policy is required. Each of at most three admitted needs contributes the first five qualified passages in rank order. Identical physical chunks are deduplicated in first-occurrence order, retaining receiving associations. A receiving association describes scope; it does not restrict which answer part may cite a passage.

Compact sources retain exact text, chunk/document/family identity and family title, declared `effective_from`, separately resolved `authority_start` / `authority_end_exclusive`, governance status and recorded applicability. Missing values remain null. Scope-enquiry metadata remains a deterministic applicability fact, not operational evidence. Every operational source is rechecked at assembly and transaction time against its original current lane. No replacement or reselection follows a failed recheck.

## Signed generation boundary

`POST /api/internal/retrieval/generation/current-policy-answer`, RC1 purpose `generation.current-policy-answer`; signed workspace and request IDs must equal body IDs. Shared schema snapshots are generated by `scripts/evaluation/generate_current_policy_contracts.py`. Request carries original question for context, admitted extractive requests, limitations and compact sources. The model is instructed to answer only admitted requests, treat sources as untrusted data, preserve conditions/applicability and distinguish event records from ongoing policy. It must not infer introduction/change dates from effective dates or claim latest records without support. These are model instructions, not a deterministic entailment proof.

Generation is one Responses request with `max_retries=0`, `store=false`, `truncation=disabled`, at most 4,096 output tokens and at most 120 seconds. Existing planner/retrieval retry policies remain separate and unchanged. No semantic reviewer, selector, extra planner or repair request is invoked.

Before generation, Python serializes the **complete provider request**, including model/settings/instructions/schema, escaped JSON input and metadata. Conservative units = UTF-8 bytes of that compact JSON + 4,096 framing units, at most 120,000. This is an application accounting limit, not a provider context-window assertion. Source text is at most 60,000 Unicode characters and at most 15 unique passages. No truncation or budget-driven reselection is allowed. Exact and one-over boundaries are tested.

Response envelope: `contract_version`, `request_id`, pinned `identity` (provider/model/prompt/adapter/reasoning/output/retry limits), `status`, `usage`, plus:

- `completed`: `result` matching output schema; Python and PHP both validate shape, disposition consistency, non-empty text and citation membership/uniqueness.
- `capacity`: `request_units`, zero provider requests. PHP source-capacity rejection also precedes generation.
- `failed`: closed reason (`unconfigured`, `provider_unavailable`, `provider_authentication`, `provider_authorisation`, `incomplete_output`, `invalid_output`). No retry. Service transport failure preserves unknown-dispatch liability; authentication, unknown envelope/identity and integrity failures propagate fail-closed.

Usage retains physical request/retry counts, tokens, latency and configured-price estimate when available. Missing provider usage/cost is null, not zero. Typed provider timeout/connection/rate-limit/invalid-response failures at existing provider retrieval stages may leave independently supported neighbours answerable, with an explicit failed-part disposition. Unknown, infrastructure/authority/integrity failures are not converted to evidence absence or partial success. Existing attempted work remains in retrieval receipts.

## Saved result consumed by Stop 3

Compose final text from validated answer parts, deterministic scope facts and explicit affected-part disclosures. Save `Message.display_text` transactionally with `GeneratedAnswer`, `AnswerPart` and `EvidenceSnapshot` associations. Membership, active corpus, source identity and current eligibility are rechecked. A persistence failure rolls back the message as well. Already-saved replies are refused before dispatch; normal run/concurrency claiming remains the existing conversation orchestrator's responsibility when Stop 3 integrates this boundary.

`GeneratedAnswer.contract_version = current-policy-answer-v1`. Stable execution configuration remains in `generation_configuration.profile`; per-run data is in the existing `temporal_context.current_policy` JSON, version `current-policy-context-v1`: planner/usage, per-lane retrieval, generation receipt, compact pool metadata and `current-policy-disposition-v2` entries. These entries distinguish admitted, partial_scope, scope_declined, ambiguity, interpretation_failure, unavailable, failed, capacity and coverage_unestablished. Non-admitted entries identify validated `affected_spans`. Malformed annotations cannot supply their own disclosure text. No schema migration or historical rewrite occurs.

Stop 3 must consume saved display text plus existing citation/scope-fact associations, not re-derive this profile's text through the legacy renderer. Existing legacy readers are unchanged. Browser/API/SSE/reload parity, workspace activation and live quality are **not delivered** by Stop 2. A legitimate dated-current question can still be mislabelled historical and safely refused: that remains a quality failure, not a successful safety result. Citation membership and exact source text do not establish semantic correctness or completeness.
