uses transition_period/transition_boundary; a dated state uses date; a requested

existing downstream ownership and timeline checks. Two independently requested
dated states use separate retrieve/date needs and may resolve to the same version.
Version identity alone does not prove unchanged operational facts. No new date-pair
wire format or semantic code-side rewrite is introduced. A missing transition now
retains `transition_authority_unresolved` through needs aggregation and the existing
controlled no-answer renderer; multiple transitions use
`ambiguous_authority_transition`, asking which update rather than repeating the
already supplied date question. Execution v24 / controlled renderer v2 identify
these response changes. Other period ambiguity and previous-version behaviour
are unchanged.

`python-produced-plan.json` is generated by the real Python adapter using controlled
HTTP transport, interpretation response and clock, not a manually assigned lineage.

`WRITE_NEEDS_CROSS_SERVICE_FIXTURE=1` for the single Python cross-service test;
normal test execution never rewrites it. This proves contract compatibility, not
live interpretation quality.

Every need's aspect is diagnostic model output only. A bounded context_spans list
(at most four) and question_span quote authorised user turns exactly. Context
quotations precede the requested clause, then any authority/fact/applicability/claim
source quote not already contained in a preceding part. Join with one space.
No generated connecting words or resolved noun substitutions. Earlier-turn nouns
are quoted to supply pronoun context; missing context is not invented. Calendar
arithmetic remains in validated typed fields, not prose. Compiled text is capped
at the existing 8,000-character downstream request limit.

Python checks the compiled executable plan. PHP independently validates all source
spans and compiles the same text before search, reranking, family review, coverage
and generation. Raw aspects remain only in diagnostic needs_plan. No raw aspect
can be used as a fallback for v4. Grounded quotes are provenance, not proof of
semantic completeness; omission/context correctness still needs interpretation
checking and independent assessment. Capacity, authority and citations unchanged.
