# Current-policy needs v1

Application disposition identity is `current-policy-disposition-v2`. Every non-admitted disposition includes `affected_spans`: validated historical partitions for mixed requests, otherwise the independently validated base question span (including ambiguity and dependent quarantine). Malformed scope annotation text is never used for disclosure. The planner wire schema is unchanged. PHP recomputes relative calendar values before validation, using the pinned London evaluation time, without changing authority kind or original wording.

Signed retrieval.plan-needs protocol, request envelope version 3, server-owned product_profile=current-policy-pool-v1. Legacy envelope 2/plan v4 is unchanged. Python producer and Laravel consumer share the plan/response schemas and examples in this directory.

Planner identity: current-policy-needs-v1 / current-policy-scope-v1 / structured-current-policy-v2. Two total planner attempts, same interpretation check, no additional model call. Provider schema excludes application-owned scope_error; response schema includes its closed quarantine reasons. Base validation always precedes local recovery.

Adapter v2 canonicalises redundant non-mixed scope annotations at the Python
producer boundary, after base validation and scope-field structural parsing.
Only a current_policy need's current_spans (with empty history_spans), or a
history need's history_spans (with empty current_spans), may be cleared. Every
span must refer to the need's own question turn, be a nonempty exact substring
with exactly one occurrence within its question_span (including overlapping
occurrences), and obey the existing count/size bounds without duplicates or
overlap. Refusal retains the original non_mixed_partition rejection. Unclear and
mixed needs are not normalised. Subsequent current-authority, restriction,
interpretation and dependency checks remain unchanged.

The parser works on a deep copy. Evaluation-only scope_normalisation/normalised
events retain the original scope fields, cleared field and cleared_span_count
(0–4), with reason redundant_matching_partition; accepted scope events and the
response contain the canonical representation. These events use the existing
default-off workspace-scoped bounded capture; they are not ordinary logs or
user-facing data. Accepted attempts still omit the full proposal, by design.

Laravel continues to require canonical non-mixed lists and rejects contradictory
or noncanonical consumer data. Only the adapter lineage and its fingerprint are
coordinated to v2; wire schema, prompt and disposition identities are unchanged.
The active response example is updated; historical run evidence is not rewritten.
Deploy API/AI together and freeze anew: old adapter identity is rejected.
normalised-producer.json is generated by the real Python adapter/parser with
controlled HTTP transport and a separately stubbed interpretation check; Python
reproducibility and Laravel consumer tests share that unchanged fixture.

Scope partitions are conditional, four exact spans per side, at most 8,000 characters combined. Duplicate, overlapping, ungrounded and ambiguous-occurrence spans are rejected. Repeated occurrences of an identical clause require a uniquely identifying quotation; no guessed offsets. Quarantined and dependent needs never execute. Current-only needs require current authority. Mixed projection removes historical authority only for the explicitly admitted current clauses and preserves applicability/fact/claim restrictions.

History, ambiguity and interpretation failure are separate typed dispositions. Scope decline wording is owned by Laravel. Event-record information is in scope; current document status does not establish latest-event status.

The Step 1 profile is default-off and deliberately refuses conversation execution until downstream pooling/generation/persistence is implemented. This is not a live product gate pass.
